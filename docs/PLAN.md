# HDTreeMap — Plan

A native disk-usage treemap viewer for macOS, Windows and Linux, built on agg-gui.
You point it at a drive or folder, it scans the folder in parallel, and it shows every
file as a shaded rectangle whose area is proportional to the file's size. The goal is
a small, fast and clean tool, not a WinDirStat clone with every feature.

Status: **approved 2026-10-10 — building M0→M6.** License MIT. Repo github.com/larsbrubaker/HDTreeMap (rust-apps submodule).

---

## 1. Prior art and what we take from each

| Project | Platform / license | What it does well | What we borrow |
|---|---|---|---|
| **WinDirStat** (KDirStat lineage) | Windows, GPL | Three linked views: directory tree, treemap, extension list. Cushion shading; colour by extension. | The three linked views, cushion shading and the extension legend. |
| **QDirStat** (KDirStat successor) | Linux/Qt, GPL | Same model as WinDirStat, plus "cleanup actions" and handling for mount points and hard links. | Staying on one filesystem, counting hard links once, a small fixed set of actions. |
| **GrandPerspective** | macOS, GPL | One clean treemap window, colours by extension, folder or date, and zoom into a folder. | Zoom in and out with a breadcrumb, a minimal UI, and a choice of colour scheme. |
| **Disk Inventory X** | macOS, GPL | WinDirStat-style layout for the Mac. | Confirms the tree + map + legend layout is what users expect. |
| **SpaceSniffer / WizTree** | Windows, closed source | Very fast. WizTree reads the NTFS MFT directly. SpaceSniffer shows results while it is still scanning. | Speed sets user expectations. Reading the MFT is out of scope for us (it needs admin and only works on Windows). |
| **dua-cli / diskonaut / gdu / ncdu** | Rust and Go TUIs | Parallel walks (dua uses `jwalk`), apparent vs allocated size, inode de-duplication, delete from inside the tool. | Parallel `jwalk` scanning, the size-mode toggle, and inode de-duplication. |
| **Filelight / Baobab** | KDE / GNOME | Sunburst (radial) charts. | Nothing in v1. A sunburst view is a possible later addition. |

Algorithms:
- **Squarified treemap** (Bruls, Huizing, van Wijk, 2000): keeps rectangles close to square, so they are easy to point at and compare.
- **Cushion treemap** (van Wijk and van de Wetering, 1999): per-pixel parabolic shading that makes the folder nesting visible without drawing borders. WinDirStat and QDirStat both use it.

## 2. v1 feature set (small but useful)

**Scanning**
- Start screen lists mounted volumes, each with a used/free bar (via the `sysinfo` crate), plus a **Choose Folder…** button (native picker via `rfd`). A path given on the command line is also accepted.
- Parallel scan with live progress: files and folders counted, bytes so far, current path, elapsed time, and Cancel.
- Size mode: **allocated** ("size on disk", the default) or **apparent**. Switching modes re-lays out the map without rescanning, because both sizes are stored.
- Correctness defaults:
  - Stay on one filesystem.
  - Don't follow symlinks or Windows junctions.
  - Count hard links once.
  - On macOS, skip `/System/Volumes/Data` firmlink duplicates when scanning `/`.
- Unreadable folders are counted and listed rather than failing the scan. On macOS a hint about Full Disk Access is shown.
- **Rescan** the whole scan or just the selected folder.

**Views** (all linked to the same selection)
1. **Treemap** (main area): squarified layout, cushion shading, files coloured by extension. Hovering a file highlights it and shows its path and size in the status bar.
2. **Folder tree** (left, in a splitter): sorted by size, with each row showing name, size and percent of parent.
3. **Extension legend** (bottom or right): the top extensions by total size, with colour swatch, total size and file count. Clicking an extension highlights all its files on the map.
4. **Breadcrumb bar** above the map shows the current zoom root. Each segment can be clicked.
5. **Status bar**: the hovered or selected path, its size, the free space on the volume, and an error count.

**Interaction**
- Click selects (and syncs the tree). Double-click a folder zooms in. Backspace, mouse back, or the breadcrumb zooms out.
- Right-click menu:
  - Reveal in Finder / Explorer / file manager
  - Open
  - Copy Path
  - Zoom Here
  - Rescan Folder
  - **Move to Trash…** (confirmed first; uses the `trash` crate, never a permanent delete). The node's size is then subtracted from the tree and the map re-laid out.
- Menu bar (native on macOS through agg-gui-shell):
  - File: Open Folder, Rescan, Quit
  - View: Size Mode, Cushion Shading on/off, Colour By (Extension / Top Folder), Zoom Out
  - Help: About

**Web demo (wasm, GitHub Pages):** the full app running in the browser against a **simulated drive**: a deterministic, realistic synthetic file tree (OS folders, apps, photos, videos, `node_modules`, caches…) generated by `hdtreemap-core::demo_fs`. The "scan" streams that tree at a believable pace, so the progress screen and the live map during the scan are shown too. Every menu, view and action works, with platform actions simulated: Move to Trash removes the node from the model, and Reveal/Open show a toast saying it's a demo. A banner makes clear it is a demo.

**Explicitly not in v1:** duplicate finder, reading the MFT or other raw filesystem structures, saved scans or history, network drive tuning, sunburst view.

## 3. Architecture

Repo layout follows Critters and AstroRock (`HDTreeMap/`, a git submodule of rust-apps):

```
HDTreeMap/
  Cargo.toml              workspace; agg-gui / agg-gui-shell from crates.io + [patch] to ../agg-gui
  CLAUDE.md  README.md  CHANGELOG.md  LICENSE
  scripts/pre-commit-check.{sh,ps1}
  .github/workflows/ci.yml        fmt + clippy -D warnings + test on ubuntu/macos/windows
  .github/workflows/release.yml   (M6) zipped binaries + macOS .app
  hdtreemap-core/         rlib — everything testable, no platform code
    src/scan/             walker (jwalk), progress, cancel, inode dedup, fs boundaries
    src/model/            arena tree, ext table, size modes, subtract-on-delete
    src/layout/           squarify + cushion coefficients (pure, no drawing)
    src/render/           cushion rasteriser → RGBA buffer, palette
    src/ui/               widgets: TreemapView, FolderTree, ExtLegend, Breadcrumb, StatusBar, StartScreen
    src/platform.rs       trait PlatformServices { pick_folder, reveal, open, trash }
  hdtreemap-native/       tiny bin: ShellConfig + agg_gui_shell::run, implements PlatformServices
  hdtreemap-wasm/         cdylib: web shell + DemoPlatform (simulated services) + demo_fs source
  demo/                   static page / bun bundle for GitHub Pages (like Critters/demo)
```

Scanning is behind a `ScanSource` abstraction: `FsScanner` (native only, `cfg(not(wasm32))`, uses jwalk/rayon) and `DemoScanner` (all targets, synthetic tree, time-sliced so it works single-threaded on wasm). Both feed the same incremental tree-builder so the UI can't tell them apart. Rayon-parallel rasterisation is native-only; wasm rasterises serially.

### 3.1 Data model (`model/`)
- **Arena tree**: `Vec<Node>` indexed by `u32`. Each node holds `parent`, `first_child`, `next_sibling`, a name index (all names in one `String` slab), `alloc_size: u64`, `apparent_size: u64`, `file_count: u32`, an extension id (`u16`), and flags (dir, error, link, etc.). That is about 40 bytes per node, so 5 million files fit in roughly 200 MB.
- Children are sorted by the active size, descending, after the scan finishes (and again when the size mode changes).
- `ExtTable`: extension id → name, total bytes, count, colour. Built from the finished tree.

### 3.2 Scanner (`scan/`)
- `jwalk` with a rayon pool, `follow_links(false)`.
- `process_read_dir` filters out entries on other devices and drops hard-link duplicates using a `(dev, ino)` set.
- Allocated size:
  - Unix: `st_blocks * 512`.
  - Windows: `GetCompressedFileSizeW` via `windows-sys` (falling back to the cluster-rounded apparent size). Reparse points are skipped.
- The scan runs on a worker thread. The worker:
  - publishes progress through atomics (counts, bytes) and a `Mutex<String>` (current path);
  - calls `UiQueue::signal_async_state_change()` at most about every 100 ms;
  - sends the finished arena back over a channel.
- Cancel is an `AtomicBool` the walker checks.
- **Design choice:** v1 shows a progress screen and then the full map, which keeps the model simple. Showing the map live while scanning (as SpaceSniffer does) is a stretch goal; the arena design doesn't rule it out.

### 3.3 Layout (`layout/`)
- Squarified layout from the zoom root down to the visible pixel size. Recursion stops when a rectangle is smaller than about 1 px², and the leftover area is drawn as one aggregated block.
- Output is a flat `Vec<LayoutRect { node, rect, cushion: [f32; 4] }>`, the cushion surface coefficients accumulated as in the van Wijk paper. The same list is used for hit testing (point → deepest rectangle, by walking the tree's rectangles).
- This is pure code that takes a tree and a rectangle and returns rectangles, so it is easy to unit-test (areas add up, nothing overlaps, everything stays in bounds, aspect ratios are sensible).

### 3.4 Rendering (`render/`)
- Cushion shading is computed per pixel, so it is not a vector-fill job. The map is rasterised straight into an RGBA buffer the size of the widget in physical pixels: for each file rectangle, every pixel gets `ambient + diffuse·max(0, n·L)`, with the normal taken from that rectangle's cushion coefficients. Bands of rows are split across rayon.
- The buffer is drawn with `draw_image_rgba_arc` (the texture is cached by `Arc` pointer). It is only re-rasterised when the size, zoom root, size mode, colour mode or tree changes.
- Hover and selection outlines and the extension highlight are drawn on top as vector strokes in `paint_overlay`, so moving the mouse never re-rasterises the map.
- Palette: 12–16 hand-picked distinct hues for the top extensions and neutral grey for the rest, the same idea as WinDirStat.
- Performance target: under 10 ms per frame when nothing has changed (agg-gui rule), and under about 150 ms to re-rasterise a 4K map with a million files. Both are measured with a stats env var, following the `CRITTERS_STATS` pattern.

### 3.5 UI widgets (`ui/`)
These are built from existing agg-gui widgets wherever possible:

| Piece | agg-gui building blocks |
|---|---|
| Overall layout | `FlexColumn` (menu, breadcrumb, `Splitter`, status bar) |
| Folder tree | `TreeView` with the size and percent drawn in the row label. If it can't show columns cleanly, add that to agg-gui rather than working around it locally. |
| Extension legend | `Table` (virtualised, sortable through `HeaderClick`) |
| Treemap | Custom `TreemapView` widget (paint, `on_event`, `tooltip_text`) |
| Context menu | `PopupMenu` |
| Menu bar | `MenuBar` / native `MenuBarModel` |
| Start screen | `Button`s, `Label`s and `ProgressBar` per volume |
| Scan progress | `ProgressBar` (indeterminate), `Label`s, Cancel `Button` |
| Confirm trash | `ModalSheet` |

All icons are Font Awesome code points, per the agg-gui rules.

## 4. Milestones

Each milestone ends green: fmt, clippy `-D warnings` and tests.

1. **M0 – Scaffold**: workspace (core / native / wasm), CLAUDE.md (copied from the Critters rules), MIT LICENSE, pre-commit scripts, CI matrix on all three OSes plus a wasm check and Pages deploy, and the start screen running both natively (real volumes) and in the browser (simulated drive).
2. **M1 – Scanner + model**: jwalk scan into the arena, both size modes, inode dedup, filesystem boundaries, cancel, and error collection. Tests use temporary directory trees (including hard links and symlinks, on Unix). Includes a CLI-ish `--dump-top N` debug flag for checking the scanner without the UI.
3. **M2 – Treemap**: squarify, cushion rasteriser, `TreemapView` with hover and status bar, progress screen, and zoom in and out with the breadcrumb. Unit tests for layout invariants and a golden-image test for the rasteriser.
4. **M3 – Linked views**: folder tree and extension legend, all synced with the map selection, plus highlight-by-extension.
5. **M4 – Actions**: context menu, reveal, open, copy path, rescan folder, Move to Trash with confirmation, and the menu bar items.
6. **M5 – Polish and perf**: measure on a real full-disk scan of each OS, **live map during the scan**, remembered window bounds and settings, and the colour-by-top-folder mode.
7. **M6 – Ship**: README with a hero screenshot, a GitHub release workflow (zipped binaries for all three OSes, a macOS `.app` via `cargo-bundle`), and the rust-apps README entry and submodule.

## 5. Risks and open questions
- **Million-node trees in `TreeView`**: it must be lazy, expanding only on demand. Check this early in M3.
- **macOS privacy**: without Full Disk Access, `~/Library` and similar folders return permission errors. We report them clearly; we don't try to get around them.
- **Windows sizes**: allocated size for compressed, sparse or OneDrive placeholder files varies. Use `GetCompressedFileSizeW` and document the behaviour.
- **Scanning speed vs WizTree**: we accept the speed of a parallel walk. Reading the MFT is a possible v2 item.
- **wasm is single-threaded**: the demo scan and the rasteriser must be time-sliced or fast enough serially.
